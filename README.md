# Tadabor

Tadabor is a Quran search and Mushaf reader packaged for Android with a local-first architecture.

## Search/display architecture

Tadabor keeps two independent Quran text layers:

- `src/data/quranData.json` — the canonical Uthmani display corpus used by the Mushaf reader.
- `src/data/searchData.json` — the plain Arabic search corpus used only by the search engine.

Both layers contain the same 6,236 ayahs and are joined by the explicit ayah identity `surahId:ayahId`. A search never searches the Uthmani display text. It searches `searchData.json`, resolves the matching `surahId` and `ayahId`, then returns the corresponding record from `quranData.json` for display.

This means Uthmani marks, dagger alif, small letters, and other Mushaf-specific characters are display concerns, not search concerns.

## Offline-first guarantees

- Quran display text is bundled locally in `src/data/quranData.json`.
- Search text is bundled locally in `src/data/searchData.json`.
- 604-page verse/page mapping is bundled locally in `src/data/quranPages.json`.
- Surah metadata is bundled locally in `src/data/surahs.json`.
- The Mushaf reader and search engine use local data only at runtime; they do not call Quran.com or another remote API.
- The Android build removes the `INTERNET` permission.
- No backend is required to run the app.

## Prepare Quran data

Run this once when preparing or refreshing the local data layers:

```bash
npm install
npm run download:quran
```

The downloader preserves an existing valid `quranData.json` and creates the independent `searchData.json` from the Quran Spelled No Diacritics edition. The search corpus is not generated by transforming the Uthmani display corpus.

`searchData.json` is a committed project asset. The GitHub Pages workflow refreshes it only as a development/build preparation step and commits it to the repository; the application itself never downloads Quran text at runtime.

## Build the web bundle

```bash
npm run build
npm run offline:check
```

The build refuses to continue unless both local Quran layers exist, each contains exactly 6,236 ayahs, every ayah has a valid `surahId:ayahId` identity, and the identities align exactly without duplicates or missing records.

## Tests

```bash
npm run test:search
```

The search tests verify that a plain-Arabic search corpus can return Uthmani display records without using the display text as the search source, including when the two corpora are deliberately stored in different orders.

## Prepare Android

```bash
npm run mobile:prepare
```

The Android project is generated by Capacitor and uses `dist/` as its local WebView bundle.

## Build APK

```bash
npm run android:build
```

The debug APK is produced at:

`android/app/build/outputs/apk/debug/app-debug.apk`

## Storage policy

Tadabor does not create an application data directory in shared/public storage for its core content. The required Quran resources are packaged with the application. Any runtime state should stay in Android app-specific storage so Android can remove it with the application on uninstall.
